# Demand Forecasting Model

Исследовательский и production-репозиторий для прогноза спроса на продукцию
пекарен.

Проект сейчас находится не в стадии продуктовой стабилизации, а в стадии проверки гипотез. Поэтому в репозитории сосуществуют несколько контуров с разным статусом зрелости.

## Текущий статус

- Production-модель: weighted weekday на восстановленном / нормализованном
  спросе. Для новых регионов используется normalized-demand weighted weekday.
  Актуальный active run и точный режим запуска всегда проверяются в
  `docs/ops/CURRENT_STATE.md`.
- Каноническое описание живого состояния: `docs/ops/CURRENT_STATE.md`.
- Production / deployment runbooks: `docs/ops/RUNBOOK.md`,
  `docs/ops/SERVICES.md`, `docs/ops/LLM_WORKFLOW.md`.
- Основной исследовательский контур: `src/experiments_v2/`
- Новый контур сравнения моделей и fixed-origin backtests: `src/model_tournament/`
- Legacy baseline pipeline: `src/preprocessing.py`, `src/models/train_and_save.py`, `run_pipeline.py`
- Production embedded app: `apps/forecast_embedded/`
- Legacy demo UI: `web/`

## Active production forecast

The current production forecast is served from the embedded ClickHouse forecast
tables and is generated by `pipelines/forecast_publish/weighted_weekday_production.py`.
The active runner uses same-weekday history over restored demand, with the
normalized-demand mode used in the current production setup.

Important operational notes:

- `forecast-production.service` on the VM is the source of production forecast
  generation.
- The embedded app reads active runs from the `*_embedded` forecast tables.
- Lead-1 snapshot history may be backfilled for statistics/reporting; this is
  documented in `docs/ops/CURRENT_STATE.md`.
- New regions use regional source tables with serving-layer ID mapping/offset
  compatibility. Check the current implementation notes before changing this
  area.

Direct alpha=.25 remains in the repository for comparison and rollback context,
but it is not the active production model unless `docs/ops/CURRENT_STATE.md`
explicitly says so for the current date.

Operational details, verification and rollback are in
[`docs/ops/CURRENT_STATE.md`](docs/ops/CURRENT_STATE.md) and
[`docs/ops/RUNBOOK.md`](docs/ops/RUNBOOK.md).

Подробное разделение ролей описано в [PROJECT_STATUS.md](PROJECT_STATUS.md).

## Что считать актуальным

Если задача связана с production-состоянием, деплоем, активной моделью,
историей backfill или работой embedded-приложения, ориентироваться нужно в
первую очередь на `docs/ops/`.

Если задача связана с текущими гипотезами, качеством модели, feature engineering
или сравнением результатов, ориентироваться нужно на `src/experiments_v2/` и
`src/model_tournament/`.

Если задача связана с историческим baseline или старым пайплайном подготовки данных, смотреть на `src/` и `run_pipeline.py`, но считать их вспомогательной legacy-веткой.

Если задача связана с production-интерфейсом пилота, смотреть на
`apps/forecast_embedded/`. Старый `web/` — это legacy/demo интерфейс и не
является источником истины по production-архитектуре.

## Основные точки входа

- Legacy pipeline: `python run_pipeline.py`
- Отдельные исследовательские запуски: `python src/experiments_v2/<experiment>/run.py`
- Model tournament / fixed-origin comparisons: `python scripts/run_model_tournament.py`
- Production weighted weekday runner:
  `python -m pipelines.forecast_publish.weighted_weekday_production --scope-source latest-base --demand-mode normalized-demand-v1 --activate`
- Demo web: `python web/app.py`

## Структура высокого уровня

- `apps/forecast_embedded/` - production embedded app для прогноза, статистики и пилотного управления
- `pipelines/forecast_publish/` - production runners и загрузка forecast runs в ClickHouse
- `src/` - базовые модули, preprocessing, monitoring, training, старые эксперименты
- `src/experiments_v2/` - текущий основной исследовательский трек
- `src/model_tournament/` - инфраструктура сравнения моделей на единой fixed-origin логике
- `scripts/` - production/research/audit scripts; перед запуском production scripts сверяться с `docs/ops/`
- `web/` - legacy демонстрационный интерфейс для просмотра прогнозов
- `tests/` - инфраструктурные и частично legacy-тесты
- `models/` - сохраненные модели и метаданные
- `reports/` - отчеты, prediction dumps, summaries

## Как использовать этот репозиторий сейчас

- Для production-задач: сначала читать `docs/ops/CURRENT_STATE.md`; для деплоя
  также `docs/ops/SERVICES.md`, `docs/ops/RUNBOOK.md`,
  `docs/ops/LLM_WORKFLOW.md`.
- Для новых ML-гипотез: продолжать работу в `src/experiments_v2/` или
  `src/model_tournament/`, если задача про сравнение моделей на общей метрике.
- Для сравнения с историческим baseline: использовать legacy pipeline как контрольную точку
- Для production UI и статистики: использовать `apps/forecast_embedded/`
- Для демонстрации старого интерфейса: использовать `web/` без требования
  полного соответствия production-контуру

## Проверки

Базовый прогон:

```bash
python -m pytest tests/ -q
```

Если в локальном окружении не установлен `catboost`, тест
`tests/test_model_tournament_fixed_origin.py` не соберётся. В таком окружении
можно временно проверить основной набор так:

```bash
python -m pytest tests/ -q --ignore=tests/test_model_tournament_fixed_origin.py
```
